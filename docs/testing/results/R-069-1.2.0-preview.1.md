## Proven causes and available client evidence

The selected profile's `genesisui-20261004-181237.log` shows Backpacks 1.3.10 bound/active
at 18:13:53, a layout with 13 equipment cells, visible backpack model meshes, and five
`refused invalid special-cell drop` warnings at 18:15:13–14. No adapter exception appears.
This supports a classification/input refusal, not an unsupported or failed adapter.

Individual-type inspection of the reference Backpacks ItemInfo proves `Get<T>` defaults to
the empty string. Its class-key rule treats null as `type#`, whereas the empty string uses
the stored type entry. AdapterBindings passed null, so ordinary ItemContainer lookup failed,
classification returned no BackpackQuiver slot and the special-cell guard rejected the drop.
Both Backpacks and Jewelcrafting default keys are now checked by exact-DLL metadata tests.
The binding uses the actual verified default parameter; no equip/transfer logic is replaced.

CraftingWindowModule's gem action explicitly requested the Inventory tab after invoking
the native socket button. The native Jewelcrafting button opens its fake container without
closing the crafting station. Preview.2 removes our forced tab transition and projects that
native container within Crafting instead. WindowCanvas expanded the board from 850 to 1200
units and refit against the same viewport fraction, explaining the smaller inventory with
a backpack. The two scale controls allow enlarging that combined board within screen bounds.

References/decompilation scratch are gitignored and remain outside the package. The local
log was read only; no game launch, profile setting write or server action was performed.
The corrections still require the [R-070](../scripts/R-070-backpack-scale-gem-flow.md) client run.
