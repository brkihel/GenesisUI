# R-049 — 0.7.0-preview.5

| Field | Value |
|---|---|
| Date | 2026-09-29 |
| Run by | Diego, own client, Windows 11, 1920×1080, GUI scale 1 |
| Evidence | `prints-tests-genesusui/full-print.jpg`, `full-print2.jpg`, LogOutput and F8 report supplied in chat |
| Result | Panel design and filter pass; inventory interaction and HUD details fail |

The inventory panels, details, weight and protection rendered. The filter list opened and
selected categories; the log confirms `filter list opened` and `filter selected`. All 111
sprites loaded. The slots initially rendered below the panel and moved briefly into place
on tab changes before shifting down again. The hint bar overlapped them. After fault and
retry, hover highlighting could remain lit. The fault injection was logged as expected; the
final F8 report listed no active fault.

Diego requested 75% window size, the same quiet frame for status and food icons, a
horizontal stamina burn with a bright edge and sparks, smoother spending and recovery, and
`.md` or `.log` for F8 reports. The 0.7.0-preview.6 candidate addresses these items.

Code inspection identified a likely interaction cause: the module set `m_player`'s
`CanvasGroup.alpha` to zero while its slots were descendants. Unity 6 still applies that
opacity to children with `ignoreParentGroups`. Slot placement was also only done when the
element list changed; the vanilla window moved afterward. The client run of R-050 is needed
to confirm both fixes.
