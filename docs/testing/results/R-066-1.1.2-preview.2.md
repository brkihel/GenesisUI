## Causes established in code

- PreviewStage framed before assigning its render-texture aspect. The first fit used the display
  aspect; subsequent equipment rebuilds used the narrow portrait aspect and increased distance.
- The copied live player lost initialized MagicaCloth behaviours during sanitization while keeping
  animator/bones. Production `VisEquipment.SetupCloth` initializes/assigns cloth runtime state.
  The new copy bakes the live pose into independent meshes rather than moving that rig/solver.
  The exact former pin position was not captured by a runtime probe; cape appearance needs R-066.
- MapWindow drew a standard panel background in front of the native map. This overlay is removed;
  native map material/input remain intact. Other causes of darkness, if any, require client evidence.
  Diego confirmed the affected view is the large map (M).
- Menu.IsVisible uses hidden-frame input hysteresis; it can report false in the frame Show activates
  m_root. Drawing now follows m_root directly, after native LateUpdates.
- TextViewer.Awake keeps rune/intro/raven roots active permanently. Dialogs incorrectly combined
  root activity with the global IsVisible predicate and showed dormant raven placeholders. Native
  animator flags now select a single reader; direct text veils also cover graphics bypassing parent
  groups and remain held through closing animations. Hover suppresses while reading.
- Edge's position-based distance field depended on UI vertex coordinates transformed by Canvas
  batching. UV-derived design units remove that dependency; the Produce halo is narrow and quiet.
